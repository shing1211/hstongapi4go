# 0014 — v2.0 removal of pkg/hstong/*

- Status: Accepted
- Date: 2026-10-11
- Supersedes: ADR 0011 §Deprecation (notice period changed from 6 months to 1 month)

## Context

ADR 0011 §Deprecation established that `pkg/hstong/*` would be marked deprecated when v-next reached feature parity, with a minimum 6-month notice period before removal. v-next reached feature parity on 2026-09-26.

This ADR records the decision made on 2026-10-11 to set a specific removal timeline for v2.0 and to shorten the deprecation notice period from 6 months to 1 month.

## Decision

### What is removed in v2.0

`pkg/hstong/*` in its entirety — all six packages:

| Package | Description |
|---------|-------------|
| `pkg/hstong/market` | Market data pull + subscribe |
| `pkg/hstong/trade` | Trade entrust, cancel, change |
| `pkg/hstong/future` | Futures entrust, cancel, modify |
| `pkg/hstong/algo` | Algo order management |
| `pkg/hstong/stream` | Push event stream |
| `pkg/hstong/session` | Login, logout, token |

### What is NOT removed

- `pkg/services` — the migration target; import path stays as-is
- `pkg/domain`, `pkg/transport`, `internal/auth` — v-next internals
- `pkg/types` — domain enums and wire structs used by both surfaces
- `client/` — the HTTP transport
- `internal/*` — private implementation

### Deprecation timeline

| Date | Event |
|------|-------|
| 2026-10-11 | `pkg/hstong/*` marked deprecated in v1.0; Go doc `// Deprecated:` added to all public symbols |
| 2026-11-11 | Deprecation window closes; no further releases of v1.x will be made after this date |
| ~2027 | v2.0 released with `pkg/hstong/*` deleted; `pkg/services` is the only public surface |

The 1-month deprecation window is shorter than the 6-month period in ADR 0011. This is appropriate because:

1. `pkg/services` has been at feature parity since 2026-09-26 — it is not a new or immature surface.
2. The migration is opt-in and incremental; both surfaces coexist for as long as the consumer chooses.
3. The consumers most likely to be affected are existing SDK users who will migrate at their own pace; a long deprecation period benefits them only if they are actively monitoring deprecation warnings.
4. The solo maintainer has limited bandwidth to support two surfaces indefinitely.

### pkg/services import path

The `pkg/services` import path does not change. A consumer migrating from `pkg/hstong/trade` to `pkg/services` uses the same `github.com/shing1211/hstongapi4go/pkg/services` import path both before and after v2.0.

## Consequences

- Consumers of `pkg/hstong/*` must migrate to `pkg/services` before upgrading to v2.0.
- Migration is documented in `docs/MIGRATION.md` with side-by-side examples for every common call.
- The deprecation markers on `pkg/hstong/*` types direct callers to `docs/MIGRATION.md`.
- v2.0 will be a breaking change for any consumer still on `pkg/hstong/*`; that is the explicit purpose of the version bump.
- ADR 0011 §Deprecation is superseded: the 6-month notice period no longer applies.

## Alternatives considered

### Option B — 6-month notice (per ADR 0011)

Keep the 6-month notice period from ADR 0011, closing ~2027-03-26. Rejected because the v-next surface has been stable since 2026-09-26 and supporting two surfaces indefinitely is disproportionate overhead for a solo maintainer.

### Option C — Retire pkg/services instead

Remove the v-next layer and keep `pkg/hstong/*` permanently. Rejected because the v-next layer represents significant engineering investment and provides a cleaner, more testable architecture.
