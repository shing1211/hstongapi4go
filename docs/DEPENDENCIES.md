# Dependencies

This document lists every dependency in `go.mod`, explains why each is required,
and clarifies what actually links when building the SDK with and without the
`otel` build tag.

## Philosophy

The SDK follows [ADR 0004](./adr/0004-minimal-dependencies.md): the standard
library is preferred, and every dependency must earn its place.  All five
`go.mod` entries above are kept to the minimum required for the stated
capability.

## Build tag: `otel`

The `otel` build tag enables OpenTelemetry traces and metrics.  It is **off by
default**.

| Build | OTel compiled? | Effect on `go.mod` |
|--------|----------------|---------------------|
| `go build ./...` | No | `go.mod` unchanged; stdlib-only |
| `go build -tags otel ./...` | Yes | OTel packages compiled and linked |

`go mod tidy` will always list all dependencies present in any build
configuration.  Running `go list -m all` therefore shows OTel even for the
default build.  To see what **actually links** without OTel:

```sh
go build -tags otel ./...   # install OTel deps first
go build ./...               # default, no OTel
go list -deps ./...          # packages that actually link
```

The OTel packages are **not** reachable from the default build's call graph.

## Direct dependencies

| Package | Version | Required for | Notes |
|---------|---------|-------------|-------|
| `google.golang.org/protobuf` | 1.36.12 | TCP push framing and protobuf DTOs | Protobuf is the native wire format for the Gateway's push channel.  Required. |
| `github.com/shopspring/decimal` | 1.4.0 | Financial decimal arithmetic | All money and quantity fields use `string` on the wire and `decimal.Decimal` internally to avoid `float64` precision loss.  Required. |
| `go.opentelemetry.io/otel` + sub-packages | 1.36.0 | Distributed tracing and metrics | **Gated by `otel` build tag.**  Not compiled in the default build.  The four sub-packages (`otel`, `otel/metric`, `otel/sdk/metric`, `otel/sdk`, `otel/trace`) are all under the same tag. |
| `go.uber.org/goleak` | 1.3.0 | Goroutine leak detection in tests | Test-only; not linked in any non-test build. |

## Indirect dependencies (automatically resolved)

These enter `go.mod` as `// indirect` and are transitive dependencies of the
direct dependencies above.  They are not imported by the SDK directly.

| Package | Introduced by | Notes |
|---------|--------------|-------|
| `github.com/go-logr/logr v1.4.2` | OTel | Logging facade used by OTel |
| `github.com/go-logr/stdr v1.2.2` | OTel | Standard library stdout adapter for logr |
| `github.com/google/uuid v1.6.0` | OTel auto/sdk | OTel's process collector uses UUIDs |
| `go.opentelemetry.io/auto/sdk v1.1.0` | OTel | Auto-instrumentation SDK; pulled in by the OTel module graph |
| `golang.org/x/sys v0.33.0` | OTel | Used by OTel SDK for OS-level operations |

## Compliance note for regulated users

A financial-services user performing a dependency audit should distinguish between
two questions:

1. **What does `go mod tidy` list?** — all nine packages above.
2. **What actually links into a built binary?** — `decimal` and `protobuf`
   in every build; OTel only when ` -tags otel` is used.

The default build (`go build ./...`) links only:

- `google.golang.org/protobuf` — required for the Gateway's TCP push protocol
- `github.com/shopspring/decimal` — required for precise financial arithmetic
- `golang.org/x/sys` — transitive from the stdlib; used by the Go runtime

OTel, `go-logr`, and `google/uuid` do not appear in the default build's
module graph.

The CI runs `govulncheck ./...` which scans the **call graph** reachable from
the SDK's packages.  Because OTel is in `go.mod` but not in the default build's
call graph, `govulncheck` may report vulnerabilities in OTel's own transitive
dependencies.  These are vulnerabilities in a **compile-time optional**
instrumentation library, not in the SDK's runtime, and do not affect a binary
built without the `otel` tag.

To scan only what actually links:

```sh
go vet ./...                          # stdlib + SDK packages only
govulncheck -dir ./client ./pkg ...  # scan only the default build's packages
```

## Changing dependencies

Any change to `go.mod` requires an [ADR](./adr/0004-minimal-dependencies.md):
adding, removing, or upgrading a dependency must be approved and documented
before merging.

## SBOM

A signed SPDX SBOM is generated by CI on every release tag.  See the
`sbom` job in `.github/workflows/release.yml`.  The SBOM lists the exact
packages that appear in the release artifacts for each OS/arch combination.
