1. Defects found and fixed
--------------------------

All seven were confirmed in source before any change. Each fix has a test that
was verified to FAIL against the pre-fix code (method: git stash the production
file, run the new test, confirm failure, restore).

ID    Defect                                                   Layer
----  -------------------------------------------------------  -----------
F1    bodySnippet embedded the first 256 bytes of a non-2xx     active
      response body verbatim, so a Gateway or proxy that echoed
      a credential put it into the returned error, and from
      there into a recorded span via EndSpan(err.Error()).
      Its comment claimed "never returns credentials".

F2    IsMutation did an exact map lookup. The Gateway also       active
      accepts "<path>Request" and "<path>RequestMsgType" for
      every route, so /trade/TradeEntrustRequest fell through
      to ClassQuery and became RETRYABLE — an alias could
      bypass the ADR 0003 single-attempt guarantee.

F3    RealFundJourList and HistoryFundJourList looped on        forward
      queryParamStr with no stalled-cursor guard, no page cap,
      and no page-size clamp (documented max 99). A Gateway
      repeating a cursor produced an unbounded loop. A
      mid-walk error also discarded completed pages.

F4    reconnectLoop read the dial address from m.conn, but      forward
      readLoop calls closeConnLocked first, so the dialer
      received "". Separately, the retry bound was guarded by
      "maxRetries > 0", making 0 mean UNLIMITED.

F5    accountid and fundaccount were absent from                active
      sensitiveKeys, contradicting ADR 0009 which states
      internal/logging redacts "account".

F6    EndSpan and the client span factory recorded                active (otel)
      err.Error() verbatim into span status and
      exception.message.

F7    FreshnessMonitor.Record returned early when seq == 0,     forward
      and seqOf always returns 0, so time-based staleness
      detection never populated in the dispatch path at all.

"active" = runs in code a current v0.1.x caller already executes.
"forward" = implemented in the v-next layer, which no production
            package imports yet (only scripts/coverage_gate.go does).

6. Residual risk accepted in E17
---------------------------------

  - Redaction is key-driven. A secret in prose with no recognisable key is
    undetectable. Pinned by TestSafeErrorLeavesUnkeyedTextAlone.
  - No replay defence: the protocol has no nonce and no idempotency key
    (ADR 0003), and the AES-ECB trade-password transform is deterministic.
  - Dedup and sequence-gap detection stay inert: the Gateway envelope carries
    no per-event sequence, so gap detection is not implementable today.
  - A backward clock jump can make an expired token acceptable again, because
    expiry is a pure comparison against the caller's clock.
  - Bare "account" and "passwordHash" stay unredacted by decision, so support
    correlation keeps working.

Full analysis, assets, trust boundaries, adversaries, and the 14-entry risk
register: docs/threat-model.md
