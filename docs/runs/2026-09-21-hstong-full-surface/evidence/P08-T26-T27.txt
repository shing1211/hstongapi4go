Codec + no-retry
- All 7 methods use m.client.JSON() -> encoding/json (ADR 0002); no proto invented.
- AddOrder/CancelOrder/CancelEntrust/ChangeOrder/ActionOrder issue exactly one
  Client.Do and the client never retries (ADR 0003).
- QueryOrderList / QueryEntrustIDList are read-only and retryable upstream.

Validation (local, before any request; errors wrap ErrInvalidParams)
- empty required fields; entrustType in {1,2}; sessionType in {0,1};
  sensitivity in {1,2,3}; action in {1,2,3,4}; positive-decimal price/amount;
  positive-int page numbers; yyyyMMdd dates; exchangeType required with stockCode.
- WithDefaultExchangeType fills an empty ExchangeType before validation.

Ambiguities modelled (from the live reference pages)
- operate-algo action set is exactly 1-4 -> closed set; unlisted values rejected.
- AddOrder table labels targetStrategy 1005 = POV while the request-example
  comments and master-order query label 1003 = TPOV and 1005 = INLINE. The
  Strategy set is therefore non-exhaustive/ambiguous: only empty is rejected and
  unknown codes are forwarded unchanged (StrategyPOV documented as ambiguous).
- Algo entrustType ('1' limit, '2' market) differs from types.EntrustType
  (where '3' is limit), so a package-local EntrustType is defined instead of
  reusing the trade enum. types.ExchangeType and types.EntrustBS are reused.
- Algo master Status ('0','1','2','3','4','5','6','8','A','C','E') differs from
  types.EntrustStatus, so a package-local Status is defined.
- QueryEntrustIdList returns only IDs: data.entrustId: []string, decoded to
  []string. No child DTO is documented.
- operate-algo param table marks exchangeType required while its request example
  omits it; modelled as required (validated) per the table.
