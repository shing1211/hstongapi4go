Defect 1 — internal/push flaky under -race under load
================================================================

Reproduction (before fix)

  go test -race -count=5 ./...
  --- FAIL: TestClientDecodesTypedNotifications (0.01s)
      client_test.go:271: OrderBook payload = &notify.TradeStockDeliverNotify{...} (ok=false)
  --- FAIL: TestClientDecodesTypedNotifications (0.03s)
      client_test.go:265: Ticker payload = &notify.OrderBookFullNotify{...} (ok=false)
  --- FAIL: TestClientDecodesTypedNotifications (0.03s)
      client_test.go:277: Broker payload = &notify.TradeStockDeliverNotify{...} (ok=false)
  FAIL
  FAIL	github.com/shing1211/hstongapi4go/internal/push	3.221s

Root cause (test timing, not a production bug)

  TestClientDecodesTypedNotifications registered one handler per notify type
  (5 dispatchers), wrote 5 frames, and then asserted the notifications arrived
  in the same cross-type order as the writes. Delivery order *across* types is
  undefined by design: SubscribeTypes gives every notify type its own
  dispatcher goroutine (internal/push/client.go), so five independent
  goroutines race to enqueue into the shared `got` channel. Under CPU load the
  arrival order changes and the positional assertions fail. No production bug:
  per-type FIFO is preserved; only cross-type ordering was (wrongly) assumed.

Fixes (test only)
  - internal/push/client_test.go
    * Added waitNotificationsByType, which collects exactly N notifications and
      indexes them by notify type (5s timeout, duplicate detection).
    * TestClientDecodesTypedNotifications now looks each payload up by type
      instead of by arrival position.
    * TestClientIgnoresHeartbeat: removed the "no extra event after 100ms
      sleep" assertion. It now writes a second real notification and asserts the
      two subscribed notifications arrive in wire order; since the read loop
      processes frames sequentially, any heartbeat-derived notification would
      have to arrive before the first push, which the first ID check rejects.
  - internal/push/verify_test.go
    * TestClientVerificationDropsTamperedFrame: removed the 150ms
      absence-after-sleep check. After the signature-mismatch error it writes a
      valid frame and requires that frame to be the next notification; a dropped
      frame cannot be delivered later because the read loop is sequential.
